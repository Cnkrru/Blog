折腾博客这件事，大概是每个写东西的人都会反复经历的循环：换框架、换主题、换部署方式，最后发现内容才是最难的部分。

## 为什么要换成 Hugo

之前的博客是基于 Vue 3 + Vite 的单页应用，文章在构建期编译成组件。它能跑，但有几个绕不开的问题：

- 每次改一个字都要重新走一遍完整的构建流程
- 文章内容被编译进 JS bundle，不利于搜索引擎抓取
- 构建产物体积随文章数量线性增长

Hugo 把这些问题的答案换了个方向：内容是 Markdown，构建是纯静态输出，一篇文章的改动只影响一个 HTML 文件。

## 这套主题做了什么

主题名叫 `hugo-theme-hello`，视觉上基本沿用了原来那套博客的设计语言：

- 玻璃拟态的卡片布局
- 首页独立的全屏页面，带粒子背景
- 五套主题色（蓝 / 青 / 墨 / 紫 / 樱），每套都有亮暗两套配色
- 桌面端左侧栏常驻，移动端自动收成抽屉

### 配色是怎么组织的

所有颜色都走 CSS 变量，主题色和明暗模式挂在 `<html>` 的 class 上，切换时只改类名：

```css
.blue.light {
  --g-color: #2563eb;
  --g-bg: #f5f6f8;
  --g-text: #1f2328;
}

.blue.dark {
  --g-color: #3b82f6;
  --g-bg: #0d1117;
  --g-text: #e6edf3;
}
```

代码高亮也接进了同一套变量，所以切换主题色时，代码块的配色会跟着一起变。

### 一个容易踩的坑

IndexedDB 的合法 key 只包含 number、string、Date、ArrayBuffer 和 Array，**boolean 不在其中**。给布尔字段建索引不会报错，但记录根本不会进索引，排查起来很费劲。

```js
// 这样建索引是无效的，pinned 是 boolean
store.createIndex('pinned', 'pinned')

// 要么改成 0/1，要么干脆在内存里排序
```
